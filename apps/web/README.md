# Nimbus web app

This workspace contains the browser app, a client-rendered React app built with Vite and routed with TanStack Router, and the Bun server that serves it with the API and WebDAV. Follow [the repository README](../../README.md) for setup, deployment, configuration, sharing semantics, and backups.

Nimbus pins Bun 1.4.4. To upgrade it, change the root `package.json` `packageManager`, the `bun-version` in `.github/workflows`, and the `Dockerfile` base image tag and digest together.

Run commands from the repository root unless noted:

```bash
bun run setup
bun dev
```

The root scripts run this workspace with `apps/web` as its working directory, so Bun loads `apps/web/.env`. `bun dev` starts the Vite dev server (port 5173, or `NIMBUS_VITE_PORT`) and the Nimbus server on `PORT`, restarting the server when its code changes. Open the Nimbus server's address: it loads pages and modules from Vite, and Vite's hot updates reach the browser over Vite's own socket. `bun run build` writes the browser app, with brotli and gzip copies of each file, to `dist`; `bun run start` serves it in production.

## Code layout

- `index.html`, `client`: the page shell, the app entry, and the router. `client/route-tree.gen.ts` is generated by the TanStack Router plugin from `routes`; commit it with route changes.
- `routes`: file-based routes. `_authed` holds the signed-in pages and sends signed-out visitors to the sign-in page; `_authed/_files` is the file browser layout and `_authed/settings` the settings layout. Route loaders start the data a page needs through the tRPC client and React Query, and links preload them on hover.
- `app/drive`: authenticated file browser, shared and saved items, and trash.
- `app/settings`: dedicated settings sidebar with Appearance, Account, WebDAV, MCP, and the admin-only Users & groups and Audit log pages.
- `app/share`: public file and folder sharing pages.
- `app/file-request`: public upload page for file requests.
- `app/auth`: sign-in, sign-up, and password reset pages.
- `server/routes`: authentication, tRPC, resumable uploads (signed-in and file requests), downloads, versions, thumbnails, public shares, backups, health, MCP, OAuth, and discovery endpoints, matched by `server/http-routes.ts`. `server/web-router.ts` adds the browser pages' own tRPC procedures to the shared API router.
- `server/start.ts`: startup migrations, the `Bun.serve` entry that routes API, WebDAV, and page requests, cleanup scheduling, and process shutdown. `server/app-shell.ts` and `server/static-files.ts` serve the page with a fresh script nonce and the built files from memory; `server/dev.ts` runs Vite and the server for `bun dev`.
- `server/db`: Drizzle schema and the SQLite connection.
- `server/drive-store.ts`: persistent accounts, grants, groups, shares, file requests, versions, homes, WebDAV properties, trash records with their suspended links and grants, bookmarks, and app passwords.
- `server/webdav.ts`: WebDAV request handling.
- `server/security-headers.ts`, `server/client-ip.ts`, `server/rate-limit.ts`: response hardening, trusted-proxy client addresses, and in-memory rate limits.
- `server/audit-log.ts` and `../../packages/api/src/audit.ts`: the audit log store and the `recordAudit` function for recording events from any server code.
- `lib/auth.ts`, `lib/auth-security.ts`, `lib/auth-audit.ts`: Better Auth configuration, Nimbus account-security endpoints, and sign-in auditing.
- `server/maintenance.ts`: trash, upload staging, file request reservation, version, and thumbnail retention.
- `server/backup.ts`: daily online database backups.
- `server/upload-publish.ts`: the staging store, publish and replace step, and resume recovery shared by both tus endpoints.
- `../../packages/api/src/file-content.ts`, `../../packages/api/src/file-versions.ts`: the one staged-write commit used by WebDAV `PUT`, the editor, and MCP, and `FileVersions.commitReplacement`, which every content replacement goes through.
- `server/thumbnails.ts`, `server/thumbnail-renderers.ts`: content-addressed thumbnail cache with bounded concurrency, and the bounded `pdftoppm` and FFmpeg subprocesses.
- `server/search.worker.ts`, `server/search-bridge.ts`: the filename index runs in a Bun worker, fed by the file watcher and reconciled every 30 minutes. The index itself is `../../packages/api/src/search-index.ts`.
- `app/drive/files/preview`: preview renderers. Each renderer, the Markdown parser, the highlighter worker, and each highlighting grammar is a separate chunk loaded only when a file of that kind is opened.
- `server/mcp`: MCP endpoint wiring, its OAuth 2.1 authorization server (`server/mcp/oauth`), and download links. Tool definitions live in `../../packages/api/src/mcp-*.ts`.
- `server/routes/oauth-*.ts`, `server/routes/discovery.ts`: MCP authorization, the server-rendered consent page, and discovery routes.
- `../../packages/api/src`: typed API routers, permission checks, safe paths, and filesystem operations shared with the server.
- `drizzle`: committed database migrations and schema snapshots.
- `e2e`: Playwright tests and fixtures, started using `../../scripts/e2e-server.ts`.

## Themes

Settings → Appearance separates the color scheme (System, Light, Dark) from the theme used for each scheme. Selecting or importing a theme preserves the current color scheme.

The built-in library includes Nimbus plus T3 Chat, Grove, Ocean, Ember, and Iris, adapted from T3 Code under the MIT license. Each palette has independently selectable light and dark variants.

Use **Add theme** to import VS Code color theme `.json` or `.jsonc` files, or search Open VSX and add an extension's color themes. Imported colors apply to Nimbus's surfaces and controls. Syntax token colors are not used. Community imports resolve theme `include` files within the extension; standalone files with includes must first be exported as a complete color theme from VS Code.

Themes and selections are stored in this browser and restored on reload. Removing a selected theme restores Nimbus's default palette for that scheme. Theme files are limited to 1 MB, extension downloads to 20 MB, and saved themes to 100.

## Database changes

Edit the relevant schema under `server/db`, then generate and inspect the migration:

```bash
bun run --cwd apps/web db:generate
bun run --cwd apps/web db:migrate
```

Commit both the generated SQL and Drizzle metadata. Startup applies the same migrations before listening. Preserve custom SQL triggers when changing account tables; they prevent removing the final active administrator. Migration tests cover both a fresh database and the original pre-migration schema.

`db:studio` opens the configured database for inspection. `db:push` is available only for disposable development databases; it bypasses migration history and must not be used for production upgrades.

## File layer benchmark

`bun run bench:files` (from the repository root) measures the file layer through its real code paths: tRPC callers, file operations, the SQLite drive store, live updates, the file watcher, the search crawl, and downloads, ZIPs and WebDAV over a node:http server that converts requests as `server/start.ts` does. It generates trees in a new directory under `/var/tmp` and deletes it afterwards (`--keep` retains it). Each metric reports latency percentiles or throughput, SQL statements per operation, peak RSS growth and the longest event-loop stall.

```bash
bun run bench:files --out=after.json                  # every scenario, about 15 minutes
bun run bench:files --only=list,save --big=10000      # selected scenarios, smaller trees
bun run bench:files --compare=before.json,after.json  # Markdown table of two runs
```

Scenarios: `list`, `access`, `safepath`, `save`, `rename`, `copy`, `events`, `watch`, `tree` (`--tree`, default 200,000 files), `burst` and `http`. `burst` creates 1,000, 5,000 and then 50,000 files in one folder while the server's watcher pipeline and three live-update subscribers run in a child process capped at 8 GB with `systemd-run --user --scope`; it reports that process's cgroup peak. `rename` uses `--big` (default 100,000) files, each with a version. The run waits while less than 8 GB of memory is available. For syscall counts, run it under `strace -f -c`. Compare runs on the same machine back to back; the numbers are not portable between machines.

The browser tests create and remove their own temporary database and files. Keep port 3100 available, or set `NIMBUS_E2E_PORT` to run on another port. Do not rebuild while browser tests run against the production build in `dist`.
